# 互动地图模块开发记录

## 1. 需求背景与目标

本次新增“互动地图”模块，目标是让用户不离开 TravelByLLM 网页，就能完成地图查看、地点搜索、路线查询和地点收藏。此前系统已经具备单城市规划、自驾路线、方案优化和历史记录等能力，但地图主要作为自驾路线结果的预览存在，用户如果想临时查看地点、收藏餐厅或比较路线，仍然需要切换到手机地图 App。

本模块的定位是一个独立的网页地图工作区：

- 用户登录后可以进入 `/map`。
- 地图是页面主画布，搜索、路线和收藏作为操作面板叠加在地图上。
- 收藏地点按当前账户持久化保存，支持分类和备注。
- 收藏地点可以直接设为互动地图路线的起点、终点或驾车途经点。
- 首版不改动 AI 规划生成链路，也不把收藏地点写入历史记录。

## 2. 最终功能范围

本次实现的首版功能包括：

- 地图加载：复用高德 JS API 2.0，通过共享加载工具初始化地图。
- 地图控件：比例尺、工具条、浏览器定位、地图点击选点、实时路况图层。
- 搜索能力：关键词搜索、输入提示、附近快捷搜索。
- 地点详情：展示地点名称、地址、收藏状态，并提供设为路线节点的快捷操作。
- 收藏管理：新增、删除、按分类筛选、按关键词检索、修改分类和备注。
- 路线查询：支持驾车、步行、骑行、公交四种模式；路线页签内可以直接搜索并设置起点和终点，驾车模式支持最多 3 个途经点。
- 路线详情：驾车、步行、骑行展示步骤摘要；公交展示第一套换乘方案中的步行、地铁、公交、铁路或打车等分段指引。
- 页面入口：顶部导航新增“互动地图”，并新增受登录保护的 `/map` 路由。
- 安全代理：前端不再读取高德 JS 安全密钥，通过后端 `/_AMapService` 代理追加安全参数。

首版没有实现自定义收藏夹、多标签、语音导航、离线地图、实时位置共享、天气覆盖层，也没有把收藏地点接入 AI 规划 prompt。

## 3. 页面与交互方案

互动地图页面采用地图优先的工作区布局。

桌面端：

- 地图铺满主要区域。
- 左侧浮动操作面板，包含“搜索 / 路线 / 收藏”三个页签。
- 右上角提供定位和实时路况开关。

移动端：

- 地图保持全屏主视觉。
- 操作面板变为底部抽屉，可以展开或收起。
- 搜索、路线和收藏功能保持同一套页签结构，避免移动端出现复杂二级导航。

地点操作围绕同一个地点结构展开。无论地点来自高德搜索、路线页签直搜、地图点击反查、当前位置还是收藏列表，前端都会统一转换成包含名称、地址、城市、区域、经纬度和可选 POI ID 的 `MapPlace`，这样收藏、地图定位和路线节点都可以复用。

路线页签内，起点和终点各自有独立搜索框。用户输入关键词后可以查看高德输入提示，回车或点击搜索按钮会展示 POI 结果；点击某个结果后，该地点才会成为有效路线节点。这样保留了“必须选择明确地点”的约束，也减少了用户在“搜索”和“路线”页签之间来回切换。

## 4. 数据库与接口设计

本次新增 Prisma 模型 `FavoritePlace`，与 `User` 建立一对多关系。

核心字段：

- `userId`：所属用户。
- `placeKey`：地点唯一键。
- `amapPoiId`：高德 POI ID，可为空。
- `name`、`address`、`cityName`、`district`：地点展示信息。
- `longitude`、`latitude`：地点坐标。
- `category`：固定分类，支持“景点、美食、住宿、交通、购物、其他”。
- `note`：用户备注，最多 200 字。

`placeKey` 由后端生成：

- 有高德 POI ID 时使用 `poi:<amapPoiId>`。
- 没有 POI ID 时使用 `coordinate:<longitude>,<latitude>`，经纬度统一保留 6 位小数。

数据库对 `(userId, placeKey)` 建立唯一约束，避免同一用户重复收藏同一地点。

新增接口：

```http
GET /api/map/favorites
POST /api/map/favorites
PUT /api/map/favorites/:id
DELETE /api/map/favorites/:id
```

这些接口全部复用现有 JWT 鉴权中间件，只能读写当前登录用户自己的收藏地点。已有接口 `POST /api/map/drive-preview` 保持兼容，自驾路线规划页面不需要修改调用方式。

## 5. 高德 API 接入与安全代理

前端新增共享工具 `frontend/src/utils/amap.ts`，统一负责：

- 设置 `window._AMapSecurityConfig.serviceHost`。
- 调用 `@amap/amap-jsapi-loader` 加载高德 JS API。
- 提供经纬度转换和读取辅助函数。

后端新增 `backend/src/routes/amapProxy.ts`，挂载路径为：

```http
/_AMapService/*
```

浏览器端高德 SDK 发起的服务请求会先进入这个代理，后端再转发到 `https://restapi.amap.com`，并追加 `.env` 中的 `AMAP_JS_SECURITY_CODE`。这样浏览器仍然只持有可公开的 `VITE_AMAP_JS_KEY`，不会暴露 JS 安全密钥。

开发环境中，Vite 同时代理：

```ts
'/api' -> 'http://127.0.0.1:3001'
'/_AMapService' -> 'http://127.0.0.1:3001'
```

已有自驾路线地图预览组件 `RouteMapPreview` 也改为使用同一套加载工具，避免项目中出现两套高德初始化逻辑。

## 6. 实际开发步骤

本次开发按以下顺序完成：

1. 复核现有路由、鉴权、Prisma 模型和高德地图预览组件，确认新增模块可以在现有基础上扩展。
2. 新增 `FavoritePlace` Prisma 模型与迁移文件，并生成 Prisma Client。
3. 新增收藏地点 service，完成输入校验、分类白名单、备注长度限制、重复收藏处理和用户数据隔离。
4. 扩展 `backend/src/routes/map.ts`，加入收藏 CRUD 接口。
5. 新增高德 JS 安全代理路由，并在 Express 应用中挂载 `/_AMapService`。
6. 安装 `lucide-react`，用于地图工作区中的图标按钮。
7. 新增前端收藏 API 类型和请求封装。
8. 抽取共享高德加载工具，并迁移已有自驾地图预览组件。
9. 新增 `/map` 互动地图页面，完成搜索、选点、收藏、路线和路况功能。
10. 更新顶部导航、Vite 代理、README 配置说明和仪表盘入口文案。
11. 二次增强路线页签：加入起终点直搜与清空、骑行模式、公交换乘分段解析，并把路线步骤从字符串数组升级为结构化步骤。

## 7. 遇到的问题与处理方式

### 7.1 高德安全密钥不能继续放在前端

已有自驾地图预览依赖 `VITE_AMAP_SECURITY_JS_CODE`。这适合本地演示，但公开部署时不理想。本次改为 `serviceHost` 代理方案，将安全密钥放到后端 `AMAP_JS_SECURITY_CODE`，前端只保留 `VITE_AMAP_JS_KEY`。

### 7.2 收藏地点来源不一致

搜索结果有 POI ID，地图点击反查不一定有 POI ID，当前位置也通常没有 POI ID。为避免前端和后端各自处理多套结构，本次统一了前端 `MapPlace` 结构，后端再统一生成 `placeKey`。

### 7.3 路线服务返回结构不完全一致

驾车、步行、骑行和公交插件返回的路线结果字段不完全相同。前端通过一组解析 helper 提取距离、时间和步骤摘要，保证四种路线模式都可以在同一面板中展示。骑行结果读取 `routes[0].rides`；公交结果读取 `plans[0].segments`，优先展示高德返回的 `instruction`，并兼容 `transit_mode`、`buslines`、`walking.steps` 等字段作为兜底。

### 7.4 Express 参数化路由的鉴权类型收窄

`/favorites/:id` 路由中，Express 的参数化 request 类型与项目自定义的 `AuthenticatedRequest` 不完全重叠。最终按现有鉴权中间件运行时约定，在参数化路由中通过 `unknown` 过渡后再读取 `authUser`，后端构建通过。

### 7.5 高德容器初始化后高度变成 0

可视验证时发现，高德 SDK 会给地图容器追加自己的 `amap-container` 样式。如果容器只依赖 `absolute inset-0`，初始化后计算高度可能变成 0，只剩控件不显示地图瓦片。本次给互动地图和原自驾预览的地图容器都补上 `h-full w-full`，保证 SDK 改写 class 后仍能继承父容器高度。

## 8. 最终结果

本次新增或改动后的关键路径：

- 页面入口：`/map`
- 前端页面：`frontend/src/pages/InteractiveMapPage.tsx`
- 高德加载工具：`frontend/src/utils/amap.ts`
- 前端地图 API：`frontend/src/api/map.ts`
- 后端收藏服务：`backend/src/services/favoritePlaceService.ts`
- 后端地图路由：`backend/src/routes/map.ts`
- 高德代理路由：`backend/src/routes/amapProxy.ts`
- 数据模型：`backend/prisma/schema.prisma`
- 迁移文件：`backend/prisma/migrations/20260525090000_add_favorite_places/migration.sql`

最终用户可以在互动地图中完成：

- 搜索地点并在地图上聚焦。
- 点击地图反查当前位置周边信息。
- 打开或关闭实时路况。
- 收藏地点，选择分类并填写备注。
- 在收藏列表中筛选、搜索、编辑和删除收藏。
- 将地点设为起点、终点或驾车途经点。
- 直接在路线页签搜索、设置、清空和交换起点/终点。
- 查询驾车、步行、骑行和公交路线，并查看距离、用时和步骤摘要。
- 查看公交换乘的具体分段方案，包括步行、地铁、公交、铁路或打车等标签、说明、距离和用时。

## 10. 后续扩展方向

后续可以继续扩展：

- 将收藏地点加入 AI 规划请求，让用户基于已收藏地点生成单城市或自驾方案。
- 增加自定义收藏夹，支持按一次出游或一个城市组织地点。
- 增加路线结果保存能力，把用户在地图中查询过的路线保存为历史记录。
- 增加地图截图或分享图，把收藏点和路线导出为展示素材。
- 对地图 SDK 做动态拆包，降低非地图页面的初始构建体积。
